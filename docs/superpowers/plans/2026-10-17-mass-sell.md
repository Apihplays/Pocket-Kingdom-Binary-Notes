# Mass-Sell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a binary patch and Python testing harness for *Pocket Kingdom: Own the World* (`6RAH.APP`) that executes a mass-sell transaction across all eligible items on the current shop page (up to 5 items).

**Architecture:** A standalone Python patch generator (`tools/patch_mass_sell.py`) that reads `6RAH.APP`, injects an ARMv4T multi-item loop into an identified code cave, redirects the shop sell confirmation call to this hook, and saves a patched binary. A validation suite verifies byte alignment, disassembly, and safety boundary conditions.

**Tech Stack:** Python 3, Capstone Disassembly Engine, ARMv4T Assembly, Git.

**Spec:** [MASS_SELL_DESIGN.md](MASS_SELL_DESIGN.md)

## Global Constraints
- Target architecture: 32-bit ARM mode (ARMv4T / Symbian E32).
- Base address: `0x10000000`.
- Code segment offset: `0x7C`.
- Executable size and relocations must remain intact.
- Equipped items must never be sold.
- Non-destructive patching: preserve original `6RAH.APP` as a backup (`6RAH.APP.orig`).

## Review Focus
1. Empty slots (item ID `0xFF` or null pointer): loop must skip without dereferencing or subtracting.
2. Equipped items (`0x100082E8` returns non-zero/equipped): loop must skip.
3. Partial page (< 5 items available): loop must terminate cleanly without out-of-bounds access.
4. Gold accumulation: gold credited must equal exact sum of individual prices.
5. Register preservation: `r4-r8, sb, sl, lr` must be restored correctly to avoid corrupting game state.
